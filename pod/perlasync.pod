=head1 NAME

perlasync - cooperative resumable execution in Perl

=head1 DESCRIPTION

This document describes the experimental generator interface.  A generator
allows a block of Perl code to suspend at an explicit C<generator_yield> and later
continue from that point.  Generators are cooperative concurrency primitives:
code can resume one generator, retain its suspended continuation, and then
resume another generator.  Calling the generator is what advances it; no
thread, event loop, or implicit scheduler is provided.

Each suspended generator owns a delimited, one-shot continuation.  The
continuation includes the Perl execution state needed to return to the yield
point, including lexical and localized state.  This permits explicit
interleaving of independent generator computations without copying their
execution state at every switch, but it is not parallel execution and does
not make shared data automatically safe.

The interface is experimental and may change or be removed in a future Perl
release.

=head1 GENERATORS

Enable the feature before using the C<generator_create> and C<generator_yield> keywords:

    use feature 'generator';

    my $counter = generator_create {
        generator_yield 1;
        generator_yield 2;
    };

The C<generator_create> expression returns a callable generator.  Calling it
runs the body until the next C<generator_yield> or until the body finishes:

    my @first  = $counter->(); # (1)
    my @second = $counter->(); # (2)
    my @done   = $counter->(); # ()

The operand of C<generator_yield> is evaluated in list context, so a yield can
produce zero, one, or many values.  An empty yield is still a suspension; it is
not exhaustion.  In scalar context the yielded value is returned as the scalar
result of the call.  C<undef> is a yielded value, not an empty result:

    my $values = generator_create { generator_yield undef };
    my @value = $values->(); # one element, whose value is undef

In scalar context, a generator call returns the first value from the yield;
in list context, it returns all yielded values.  An empty yield produces no
values in either context but still suspends the generator.  The body runs in
the context of the call that resumes it.  Lexical variables,
loop state, and localization in the body remain in effect across an
C<generator_yield> and are restored when the generator finishes.

Arguments passed to the first call are the generator body's normal arguments:

    my $adder = generator_create {
        my ($x, $y) = @_;
        my $next = generator_yield($x + $y);
        return $next;
    };

    $adder->(2, 3); # yields 5

Arguments passed to later calls are returned by the suspended
C<generator_yield>.  In list context all arguments are returned; in scalar
context the first argument is returned, and in void context they are
discarded.
The initial arguments can also be bound with a signature (with the
C<signatures> feature enabled):

    my $adder = generator_create ($x, $y) {
        my $next = generator_yield($x + $y);
        return $next;
    };

An explicit C<return> can provide the final list returned by the completing
call.  Once that call has completed, C<generator_exhausted> reports true and
further calls fail.

=head1 LIFETIME AND ERRORS

When the body finishes without another C<generator_yield>, the completing call
returns its explicit return list (or an empty list) and the generator becomes
exhausted.  Exhaustion is permanent: a
later call raises an exception.  A generator is also permanently failed if an
uncaught exception leaves its body.  That exception is propagated by the call
which resumes the generator, and later calls raise an invalid-resume
exception.  An exception caught by an C<eval> inside the body does not by
itself terminate the generator.

The C<generator_exhausted> keyword tests completion without resuming the generator:

    generator_exhausted $counter

It returns true only after a resume has run the body to completion.  It returns
false while the generator is new or
suspended, and also for a failed generator.  Testing exhaustion does not
advance the sequence.

A generator cannot be resumed while it is already running.  This includes a
generator attempting to call itself before it has reached
C<generator_yield>.  A suspended generator is a one-shot continuation; it is
not copied when it is assigned or passed around, so all references designate
the same continuation.

=head1 WHERE C<generator_yield> MAY BE USED

C<generator_yield> is valid only lexically inside an C<generator_create> block.
It is not valid in an ordinary subroutine or in callback code such as C<sort>, C<map>,
C<grep>, or a regular-expression code block.  Callback code cannot suspend
the operation that invoked it.

=head1 SEE ALSO

L<perlfunc/generator_create BLOCK> describes the C<generator_create> keyword in
the Perl function reference.  L<perlembed> and L<perlinterp> describe other forms of
embedding and interpreter execution; they do not provide generator scheduling.
