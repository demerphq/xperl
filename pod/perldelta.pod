=head2 Experimental SipHash builtins

C<builtin::siphash> computes SipHash with caller-selected compression and
finalization rounds. C<builtin::siphash_1_3> and C<builtin::siphash_2_4>
provide the common fixed variants. They accept a byte string and an optional
16-byte seed, and return an eight-byte digest. The default seed is the
published test-vector key, so callers handling untrusted input should supply
a secret seed. See L<builtin/siphash>.

=head2 Experimental jump consistent hash builtins

C<builtin::jumphash_integer> maps an unsigned 64-bit key to a bucket number.
C<builtin::jumphash_string> first hashes a byte string with a fixed-key
SipHash-2-4, then performs the same mapping. Adding one bucket only moves keys
to the new bucket. See L<builtin/jumphash_integer>.

=head2 Custom constructors for native classes

Native classes expose their generated constructor as C<CONSTRUCT>. A class without
its own C<new> receives an alias to C<CONSTRUCT>, preserving default construction.
A class can instead declare an ordinary C<sub new>, including a signature,
and delegate to C<CONSTRUCT> after processing its arguments. See
L<perlclass/Construction>.

=head2 Experimental inheritance from conventional packages

Modern class objects are ordinary blessed references. Class-name
C<CONSTRUCT> creates an undef scalar referent. Object-invoked C<CONSTRUCT>
attaches lexical fields to the existing blessed reference, retaining its
payload and identity. Conventional and modern methods receive the same
C<$self>. The former C<:blessed_self> field attribute is removed.

Modern fields form the union of the effective hierarchy, including modern
ancestors reached through conventional packages and shared diamonds.
Different classes may own distinct same-named fields. Field-hash conversion
always groups original fields by storage-owner class, including single-owner
objects; fieldless and alias-only classes add no buckets. Its C<'$self'>
entry retains the actual blessed object. One-argument restoration attaches
fields to that same referent. Data::Dumper defers normal restoration until
reference fixups finish. This preserves same-named values and existing
field aliases during reconstruction. Use C<field $name :inherited> to
explicitly share one unambiguous ancestor declaration.
C<:private> prevents descendants from binding that field. Inherited aliases
add no storage or initialization and do not make other ancestor fields
implicitly visible. See L<perlclass/Field attributes>.

C<TEARDOWN> releases modern state after normal C<DESTROY>, or before
reblessing into another package. It runs once through normal method lookup,
with parent delegation explicit and no C<AUTOLOAD> fallback. See
L<perlclass/Destruction>.

C<Data::Dumper> and the field-hash builtins preserve ordinary payloads along
with modern fields. C<builtin::is_class_object> queries attached storage,
and C<class_object_from_hash> accepts an optional ordinary payload reference.
C<Storable> requires explicit hooks for modern fields rather than silently
dropping their storage.

=head2 Experimental diagnostic catalog lookup

The experimental C<builtin::get_diagnostic_data> function returns a fresh
metadata hash reference for a diagnostic identified by catalog number or
code. The result includes available translated template cases, selector
criteria, and parameter layout information. Unknown identifiers return
C<undef>. See L<builtin/get_diagnostic_data>.

=head2 Experimental integer plural forms

The experimental C<builtin::cardinal_plural_form($language, $n)> and
C<builtin::ordinal_plural_form($language, $n)> functions return grammatical
plural categories for unsigned integers. They support all languages
represented by the retained CLDR 49 definitions, independently of
installed or loaded diagnostic packs. Language tags and code-based POSIX
locale names are accepted, including regional plural overrides. Known
languages without an explicit ordinal rule use C<other>; unsupported
languages return C<undef>.
See L<builtin/cardinal_plural_form>.

=head2 Additional diagnostic translations

The experimental diagnostic catalog adds Simplified Chinese (C<zh>),
Persian (C<fa>), Russian (C<ru>), Ukrainian (C<uk>) and Welsh (C<cy>)
translations, integer plural rules and
shared operation vocabulary. Chinese cardinal and ordinal categories are
always C<other>. Persian cardinal plural categories use C<one>
for 0 and 1, and C<other> for all larger unsigned integers; its ordinal
category is always C<other>.
Translations are machine-generated drafts and have not had native linguistic
review. For example, C<PERL_DIAG_RENDER=fa:legacy> selects Persian text.

The Serbian (C<sr>) pack uses Cyrillic text and shared operation vocabulary.
Its cardinal categories are C<one>, C<few> and C<other>; its ordinal
category is always C<other>. Like the other packs, its translations are
machine-generated drafts awaiting native linguistic review.

The Polish (C<pl>) pack includes translated diagnostics and shared operation
vocabulary with grammatical cases. Its integer cardinal categories distinguish
C<one> (only 1), C<few> (counts ending in 2-4 except those ending in
12-14), and C<many> (including 0 and 21).
Its ordinal category is always C<other>. The translations are machine-generated
drafts awaiting native linguistic review.

Diagnostic packs now accept three-letter language codes. The Klingon
(C<tlh>) pack adds translated diagnostics and shared operation vocabulary;
its own cardinal and ordinal rules use C<other>. The independent builtin
CLDR plural lookup has no C<tlh> entry. Its translations are machine-generated
drafts awaiting linguistic review.

Missing translations in the existing German, Spanish, French, Icelandic,
Italian, Dutch and Portuguese catalogs have also been filled in. Stale French
UTF-8 sequence-length wording has been updated. Translation repair records
source freshness separately from linguistic review.

=head2 Experimental structured core exceptions

Annotated rendering respects a final newline in user warning and error
messages: it adds no source location to the header or message body. The
structured diagnostic retains its source location for inspection.

Annotated rendering shares consecutive identical headers and places
contained hints on separate indented lines under their parent's header.
It preserves nearby parser source text and avoids adding a location after
a message that already ends in a newline. Operator-expected hints now have
C<NOTE> severity; the parent controls their syntax-warning policy.

Parser errors and catalogued C<croak> and C<DIE> failures now deliver
C<XPerl::Exception> objects by default. Plain C<die "text"> and
C<warn "text"> create C<ERROR_USER_TEXT> and C<WARNING_USER_TEXT> diagnostics
with the supplied text as an argument. Catalogued warnings also deliver objects,
including when they become fatal.
The default stringification preserves the previous error text;
C<PERL_DIAG_RENDER=Dumper> selects a C<Data::Dumper> view. Other error paths
still use their existing values.
Carp formats caught C<XPerl::Exception> values as text before adding a caller
location. Other reference exceptions keep their identity when passed to Carp.
The C<XPerl::Exception> and C<XPerl::Diagnostic> methods are built into the
interpreter and work in miniperl without loading their Perl files. Dumper
rendering falls back to legacy text when C<Data::Dumper> is unavailable.
Both classes now provide C<as_json>. Exception C<render('json')> and
C<PERL_DIAG_RENDER=json> use the same versioned JSON shape. The built-in
encoder works in miniperl without a JSON module and leaves Dumper available
for development.

C<XPerl::Exception> and C<XPerl::Diagnostic> share the C<XPerl::DiagGroup>
operations C<contents>, C<contents_count>, C<append>, C<contains>, and
C<has_errors>. Both store their diagnostic entries under C<contents>.
Diagnostic storage is allocated when entries are added. JSON and Dumper
records use C<contents> for diagnostic lists at every level.
Applications can traverse the graph with C<diagnostics> and query by symbolic
code and named parameters with C<find_diagnostic> or C<has_diagnostic>.
These methods are available at startup without loading C<XPerl::DiagGroup>.

Diagnostics emitted by generated core macros now record the C source file
and line of the macro call. Annotated output shows this location in the
header, and JSON exposes it under C<c_source>.

=head2 Experimental data-shape matching

The documentation is now split into L<perldispatchontut>, a progressive
tutorial, and L<perldispatchon>, the detailed language reference.

Declaring the same capture name twice within one dispatch-on clause is now a
compile-time error, including across nested shapes and different capture forms.
Repeated pins remain valid, and regex named-capture rules are unchanged. Use distinct
capture names and a guard to require equal values.

Empty array and hash shapes, C<on ([])> and C<on ({})>, now match
empty containers. They also work in nested and class-qualified shapes.

Duplicate named captures in separate shape regexes now consistently bind
from the first regex in source order, even when constraint scheduling changes
execution order. Hash wildcard values check key presence without fetching
the value, matching the capture-free behavior of array wildcards.

Structural requirements now precede capture-only reads, including in nested
shapes. Literal constraints are checked before other requirements at each
aggregate level. This changes the observable order of tied and overloaded
operations and pattern calls; see L<perldispatchon>.

Tentative captures and traversal values are retained across callbacks.
An exception-safe owner releases captured values on normal temporary cleanup
or unwinding. Retention preserves scalar lifetime, not a frozen value.

Mixed signed/unsigned dispatch bounds no longer reject valid unsigned
matches. Tied hash shapes check key existence before fetching a value, so
a missing key cannot satisfy an C<undef> value shape.

Array tail captures copy element values instead of aliasing source slots.
Pinned comparisons distinguish C<undef> from
the empty string, while two undefined values still compare equal.

Dispatch/on now consistently preserves string-versus-number distinctions
after numeric caching, handles sparse array slots as C<undef>, and compares
equivalent byte and UTF-8 string representations correctly. Pinned
references use identity. Malformed hash shapes are diagnosed during
compilation. Subject and native field-view ownership fixes prevent leaks,
and scalar-reference shapes reject non-scalar referents without attempting
invalid copies.

Capture names repeated across separate regexes in one dispatch-on clause now
produce a C<syntax> warning: only the first regex supplies the lexical
binding.  Duplicate names within a single regex retain their usual behavior.

The experimental C<dispatch_on> feature uses the C<dispatch> and C<on>
keywords. These replace the earlier experimental C<case> and C<match> spellings
to avoid conflicts with syntax planned for Perl core. The feature adds ordered
C<on> clauses. Data shapes can match scalar values, nested array and hash
references, regular expressions, wildcards, and pinned lexical values. The
dispatch subject is an ordinary Perl expression. Shared predicates are
provided by C<dispatch::Predicates>; user-defined predicates are ordinary
subs whose first signature parameter is named C<$subject>.
Predicate arguments are constants or pinned values, and captures use
C<$name = PATTERN>. The standard numeric predicates are C<Int>, C<Integer>,
C<Num>, and C<Number>. See L<perldispatchon> and
L<perlsyn/Experimental Data-Shape Matching> for the current experimental
design and limitations. A subject can be named with C<dispatch my $name (EXPR)>;
an unnamed dispatch temporarily localizes C<$_>. C<redo> retries matching against
the current subject without reevaluating C<EXPR>, while C<next> and C<last>
leave the dispatch. The former C<with> clause and subject C<as> syntax are not
supported. Existing lexical values are pinned directly with C<^$name>.
Pattern variables have one consistent rule: a bare name introduces a capture,
even if it matches the spelling of the dispatch subject. Prefix the name with
C<^> to compare against an existing lexical value.

Data shapes may also use zero-argument function and method calls as scalar
values. Calls are made in scalar context when a dispatch-on clause is tried.
Calls with arguments are predicates when the called sub has a leading
C<$subject> signature parameter. Repeating a constant data shape
produces a C<syntax> warning because the later clause can never match; the first clause
remains selected.  The warning includes the repeated constant and its source
location.

Captures local to a dispatch-on clause retain ordinary lexical lifetime when
kept alive by closures or references, including when a guard rejects that
clause. Nested regex shapes bind each regex's named captures independently.
Array shapes
and capture sets no longer have a fixed 64-element limit.  Slurp minima are
checked against C<2**32 - 1> before decimal accumulation can overflow.

Duplicate constant keys in hash shapes are compile-time errors.  Runtime
key collisions do not raise duplicate-key errors; exact hash matching
checks coverage of distinct keys rather than counting syntactic pairs.

Static regular expressions used by open array or hash shapes are compiled once
and reused for each candidate.  Regex code blocks, C<(?{ ... })> and
C<(??{ ... })>, are currently rejected while a dispatch pattern is compiled so
that their side effects cannot be silently discarded.  Unicode and byte-string
behavior remains under the control of the regular-expression engine.  Dynamic
regular expressions, such as C</thing-$re-thing/>, are also rejected in a
data-shape pattern; use an ordinary Perl guard after C<if> when the regular
expression must be built or interpolated at run time.

Array data shapes may capture a final tail with C<@name>, or require a minimum
tail length with C<@name:N>. Shared predicates include C<RefVal>,
C<NonRefVal>, and C<BlessedVal>; write captures as assignments such as
C<$reference = RefVal()>. A bare target name remains a capture even if a
same-named lexical exists outside the dispatch.

Concatenated string shapes accept double-quoted constant fragments, including
Perl's normal escape semantics. Variable interpolation in those strings is
rejected; write captures as separate concatenation operands instead.

Literal and pinned scalar values now select numeric or string comparison from
their Perl type and flags. Numeric-only values use numeric C<==> semantics;
string-bearing and ambiguous dual-valued scalars use string C<eq> semantics.
The exact form C<0 + PATTERN> forces numeric comparison, while stringifying a
pin can use the existing concatenation form C<"" . ^$name>. Literal runs in a
concatenation pattern are combined, and captures must have a non-empty literal
boundary between them. Numeric conversion during matching does not emit
conversion warnings: a comparison that would produce an uninitialized or
non-numeric conversion warning is a non-match, even when warnings are disabled.
Warnings from overloaded comparison code remain visible.

Data-shape patterns can now capture a value and constrain it with a nested
pattern using C<$name = PATTERN>. The name is a capture local to the
dispatch-on clause, not an assignment to an existing variable. The nested
pattern must match for the clause to succeed.

Blessed references may use a class-qualified data shape.  Hash object shapes
check quoted field names, array object shapes check positional values, and a
reference object shape can bind a scalar referent.  Class checks use Perl's
C<isa> behavior, so subclasses match and an overridden C<isa> method
participates in the check.  After the class check succeeds, patterns inspect
the object structure directly without calling constructors or accessors.
Native Perl class objects backed by the class field-map representation are
supported. Missing fields do not match; tied or magical nested values use
ordinary read semantics, and overload is used only when the selected pattern
requires conversion.

Class-qualified shapes introduce captures in the dispatch-on clause's lexical
scope, including its guard.  Captures do not overwrite outer variables with
the same names.  A defect that could select a class field's pad entry and
crash when a capture shared its name has been fixed.

Freeing an array-tail pattern no longer treats its minimum element count as
a lexical pad index, which could crash during eval cleanup.

An existing scalar can also be pinned directly in a data shape with the
pattern-only C<^$name> form. Its current value is read when the pin is tested,
and ordinary caret operators retain their normal meaning outside C<on>
data shapes.

String shapes may contain multiple unbound scalars inside literal
concatenation, for example:

    dispatch ($text) {
        on ("a" . $first . "b" . $second . "c") {
            say "first=$first second=$second";
        }
    }

Captures are resolved from left to right using the shortest value bounded by
the next literal or pinned fragment.  Empty captures are allowed.  Adjacent
unpinned captures, repeated capture names, and fragments separated only by an
empty literal are errors. A name written with the pattern-only C<^> prefix is
a pinned existing lexical and must match its current value rather than capture
new text. Concatenation supports only
literal, capture, and pinned fragments; arithmetic, calls, and other
unsupported expressions throw an exception.

More generally, unsupported or ambiguous data-shape syntax is rejected
explicitly.  It is never silently ignored, treated as a non-match, or
reinterpreted as ordinary Perl code.  See L<perldispatchon> and L<perldiag>
for the current rules and diagnostics.

=head2 Lexical namespaces

The experimental C<namespaces> feature provides lexical namespace prefixes,
the C<namespace> declaration and block form, C<__NAMESPACE__>, and lexical
package aliases using C<use ... as ...>.  See L<perlnamespace>.

=head2 Localizable random number generators

The new C<${^RNG}> variable can be localized to select a user-supplied random
number generator for C<rand>, C<srand>, and C<builtin::rand_bytes>.  An object
provider implements C<rand_bytes> and C<srand> methods.  The provider supplies
the requested number of random bytes to C<rand_bytes>, while C<srand> receives
the normalized seed value.

The new L<RNG::Seed> class represents replayable string or raw seed material
for a provider.  The bundled generators other than Drand48 wrap false seed
strings in always-true seed objects which preserve their string value and
reproduce the same sequence when reused.  Secure automatic initialization
returns a redacted seed token,
which records the provider but cannot be used to reproduce the state.

When C<${^RNG}> is undefined, Perl continues to use its normal random number
generator.  The provider's state is independent of Perl's default generator,
and localizing C<${^RNG}> does not copy or restore that state.  See
L<perlrng>, L<perlfunc/rand EXPR>, and L<perlvar/${^RNG}> for more information.

An XS provider may also implement the optional
C<get_rand_U01_XS_func_addr> and C<get_rand_U01_XS_state_addr> methods.  When
they return a valid callback address and state pointer, C<rand> can obtain a
uniform C<[0,1)> value without Perl method dispatch.  The ordinary
C<rand_bytes> interface remains the portable provider protocol.

Only C<undef> or a C<RNG::Provider> object can be assigned to C<${^RNG}>.
Other scalar values are rejected at assignment.

=head2 Experimental generators

The experimental C<generator> feature creates a callable one-shot generator
from a block.  Each call resumes the block until its next C<yield>,
returning the yielded list in list context or its first value in scalar
context.  Separate generators can be resumed in an explicitly interleaved,
cooperative-concurrency pattern.  Generator calls can also send arguments
back to the suspended C<yield>.  See L<perlfunc/gen
BLOCK> and L<perlgenerator> for details.

The C<running>, C<completed>, C<failed>, and
C<exhausted> predicates are methods on generator objects and functions in the
C<generator::> package.  The C<generator> pragma enables the feature and makes
the package interface available.

=head2 Callable iterators

The experimental C<iterator> package can bless an ordinary code reference as
a callable iterator.  Its lifecycle can be inspected with the C<running>,
C<completed>, C<failed>, and C<exhausted> predicates and changed with
C<set_state>.  An iterator remains callable as the same code reference, and
an uncaught exception escaping its body is rethrown without automatically
changing its state; the implementation or caller may explicitly mark it
failed.  Generators inherit this protocol while continuing to manage their
continuation state internally.  See L<perlgenerator/CALLABLE ITERATORS>.

=head2 Complete experimental APIs with C<-E>

The C<-E> command-line switch now enables the complete experimental feature
set and imports the complete builtin set, including the generator syntax and
its supporting builtins.  This is an XPerl extension to the traditional
version-bundle behaviour of C<-E>.

=head2 Data::Dumper supports class objects

C<Data::Dumper> can now dump objects created by the experimental C<class>
feature.  It represents their fields with the experimental
C<builtin::class_object_to_hash> API and emits code using
C<builtin::class_object_from_hash> to recreate the object without invoking
its constructor.  Field values are shared rather than recursively copied.

=head2 Data::Dumper supports class objects

C<Data::Dumper> can now dump objects created by the experimental C<class>
feature.  It represents their fields with the experimental
C<builtin::class_object_to_hash> API and emits code using
C<builtin::class_object_from_hash> to recreate the object without invoking
its constructor.  Field values are shared rather than recursively copied.

=head2 Data::Dumper Unicode preservation is opt in

C<Data::Dumper> keeps traditional quoting and hexadecimal escapes by
default. C<PreserveUnicode(1)> preserves UTF-8 flagged strings when dumped
and evaluated, using C<\N{U+...}> escapes. C<PreserveUnicode('name')> uses
Unicode character names where available. The diagnostic catalog generators
request name mode explicitly.

=head2 Repeated UTF-8 decoding

C<utf8::repeat_decode($string, $force)> stringifies and modifies its argument
in place to remove repeated UTF-8 encoding. It stops when a conversion fails
or a pass does not shrink the byte length. The optional C<$force> ensures a
UTF-8 flagged result. See L<utf8>.

=over 4

=item *

Case-insensitive literal alternatives such as C<foo|bar|a_word|_qux> can
compile into a single trie again.  Characters that do not participate in
Unicode case folding can join neighboring folded literals after the
optimizer records their fixed substrings.
L<[GH #19953]|https://github.com/Perl/perl5/issues/19953>

=item *

Non-folded trie matching against native byte strings now consumes a
character's encoded octets in one iteration. This reduces reader bookkeeping
when the character requires two UTF-8 or UTF-EBCDIC octets.

=item *

The Aho-Corasick regex scanner uses Boyer-Moore-Horspool shift tables to skip
positions where no literal alternative can start.  It can also skip repeated
blocks of octets that cannot start an alternative.  These filters apply to
eligible case-sensitive literals, with separate shift tables for Latin-1 and
UTF-8 targets.

Eligible case-insensitive literal alternatives use a start-octet map that
includes their possible folds.  They do not use the shift tables, because
folding can change encoded lengths.  Locale-dependent folding uses the
existing scanner.

The scanner also reduces the cost of tracking match positions, especially
for case-sensitive matching against non-UTF-8 targets, and avoids repeated
alignment checks while finding a rejected block of octets.

=back

=head2 New Modules and Pragmata

=over 4

=item *

L<TOML::Tiny> 0.22 is bundled with XPerl for configuration files. It parses
date and time values as strings by default. The optional DateTime format
modules are not bundled.

=item *

L<XGraph> is bundled as an XS-backed directed graph.  It provides stable
vertex IDs, optional names, labeled edges, adjacency and path operations,
and graph algorithms.  Graph errors currently use C<XPERL.GRAPH.*> codes.

=item *

L<Net::SSLeay> 1.97_01 and L<IO::Socket::SSL> 2.099 are bundled with XPerl.
Building Net::SSLeay requires OpenSSL or LibreSSL headers and libraries.
This Net::SSLeay development release supports OpenSSL 4.0 and later.
IO::Socket::SSL provides the higher-level Perl socket interface.

=item *

L<RNG::HMAC_DRBG> provides an HMAC-SHA-256 provider following the HMAC_DRBG
construction in NIST SP 800-90A.  L<RNG::PCG> provides a small XS
implementation of the two-dimensional PCG-XSH-RR pseudorandom number
generator, while L<RNG::Wyrand> and L<RNG::Xoshiro> provide additional fast XS
generators.  They can be used directly or as providers for the new C<${^RNG}>
variable.

=item *

Diagnostic translations are provided by eighteen optional
C<XPerl::DiagPack::XX> XS modules. English remains compiled into Perl and
miniperl. Requiring a pack registers its capability without selecting it;
C<use XPerl::DiagPack qw(all)> loads installed packs. The provisional
L<diagpack> pragma selects a language lexically, and diagnostics retain that
choice for later rendering. Explicit rendering languages override captured
choices. Startup loads the language selected by C<PERL_DIAG_RENDER>, except
in taint mode; missing translations fall back to English.

Each pack provides C<metadata> and C<render($diagnostic)>. Direct rendering
returns the message body or C<undef> for a miss, with no fallback, locations,
grouping, hooks or delivery. Core rendering owns those operations and retries
English with fresh argument values when a pack misses.

=item *

L<XPerl::REPL> is the engine of the new F<xperl-repl> interactive shell.
It keeps lexical variables, the package and pragmas between inputs,
continues unfinished input by reading the parser's structured
diagnostics, and renders errors as structured exceptions.

=item *

L<Term::ReadLine::XPerl> is a small line editor written in C, with no
external library, behind the L<Term::ReadLine> interface: history with
prefix search and ctrl-r, tab completion through a callback, key
bindings, UTF-8 aware editing and coloured prompts.  It is built on
Unix-like systems only.

=head2 F<xperl-repl>

=over 4

=item *

F<xperl-repl> is a new interactive shell for xperl.  Variables, the
package and pragmas persist from one input to the next, unfinished input
is continued, and results and errors are printed as they are produced.
On a terminal it edits lines with L<Term::ReadLine::XPerl>, with history
in F<~/.xperl/repl_history>; an rc file in F<~/.xperl/replrc> can
configure the session.  Without a terminal it reads standard input with
no prompts.  See L<XPerl::REPL>.

=back

=item * t/TEST and t/harness now run generated tests

F<t/TEST> and F<t/harness> are the programs which are the engines underneath
C<make test> and C<make test_harness>.  Up till now the list of test files that
they run was composed by examination of F<MANIFEST>.  However in 2020 the test

during that library's own build process from data files found underneath that
directory.  As such they were no longer listed as test files in F<MANIFEST> --
but F<t/TEST> and F<t/harness> were not updated to account for the possibility
of generated tests in addition to "MANIFEST-listed" tests.  This was not
noticed until L<[GH #24855]|https://github.com/Perl/perl5/issues/24855>.

This has been corrected.  Testers will now see F<dist/Devel-PPPort/t/*.t> test
files being run as part of C<make test> and C<make test_harness>.  In
addition, F<t/porting/test_testlist.t> now verifies that generated tests are
being run and more thoroughly exercises the various ways in which running the
test suite can be triggered.

=head1 Internal Changes

=head2 XPerl extension detection

F<perl.h> defines C<XPERL_VERSION> to C<1>. C<XPERL> remains an alias for
existing C and XS extensions. Perl code can test C<${^XPERL_VERSION}>,
which is C<1> on XPerl and undefined on ordinary Perl. C<perl -V> reports
the XPerl version explicitly.

=head2 Experimental XPerl hash storage

Ordinary hashes now use a compact array of two-pointer C<HE> records and
an independently grown index. By default, indexed hashes use integer chains:
packed bucket heads point to a packed per-entry next-link array. The link and
head identifiers use one, two, or four bytes; fingerprints are disabled by
default. Open addressing remains available by selecting
C<PERL_HASH_INDEX_OA>. With the default positive
threshold, a singleton uses one compact 16-byte C<HE> from the arena on
64-bit builds. At threshold zero, hashes use indexed storage from the first
key. By default, hashes with up to four keys use a dense C<HE> array with
linear search and promote to indexed storage after the fourth key.
C<PERL_HASH_LINEAR_MAX> can select a threshold of zero, two, four, or eight
entries. In OA builds, the index stores adaptive-width entry identifiers
only; the full cached hash remains in the entry's C<HEK>. Index capacity
remains a power of two. Through an index capacity of 16,384 slots, OA entry
capacity is C<floor(2*index_capacity/3)>, and filling that entry allocation
can trigger an index rebuild. The following load, tombstone, growth, and
shrink rules describe OA indexes. Above that size, index pressure triggers a
rebuild when live entries plus tombstones reach
C<floor(2*index_capacity/3)>. Above the
coupled range, the full entry array grows independently by 25 percent.
Entry compaction uses a
20 percent hole threshold at all sizes, with no byte threshold. A full entry
array compacts when it reaches this threshold. A non-full array compacts at
this threshold when its proposed entry capacity,
C<live + floor(live/4) + 1> with a minimum of eight, is at most half its
current capacity. Otherwise a full entry array grows under the sizing rules
below. Deletion alone does not rebuild either array. These are standalone
insertion checks. An index rebuild that is otherwise required also packs
entries when holes meet the 20 percent threshold; that rebuild does not use
the standalone HE shrink test.

After any required full-entry compaction, when index occupancy reaches
two-thirds, tombstones are cleared at the same index capacity if they make
up at least half of occupied slots. With fewer tombstones, the index grows
to preserve the live-load limit. Growth uses the next power of two that can
hold C<3 * live> entries, with a minimum of eight slots. Shrinking is
considered only during compaction. The target index must be at most half its
previous capacity. Its target is the next power of two that can hold
C<3 * (live + 1)> entries, with a minimum of eight slots. The entry array
can shrink independently when its target capacity,
C<live + floor(live/4) + 1> (minimum eight), is at most half its previous
capacity. Otherwise existing capacities are retained. Rebuilds, including
compaction, reuse the index allocation when index and entry capacities are
unchanged. Without compaction, entry positions and holes are preserved. For
initial sizing and ordinary growth through 16,384 index slots, entry capacity
remains coupled to two-thirds of index capacity. Above that size, entry capacity grows
independently. A shrink can leave entry capacity decoupled from index
capacity. Changing it uses C<Renew> and may relocate the entry array.
Explicit C<hv_ksplit()> reservation allocates entry space for the requested
count plus existing holes above the coupled range, including when the index
already has enough capacity. New-key insertion reuses its initial probe
result unless an index rebuild invalidates it.
The entry allocation can exceed index capacity, but identifier width
continues to depend on index capacity: one byte through 128 slots, two bytes
through 32,768 slots, and four bytes above that. The
entry traversal order is an implementation detail and does not guarantee
public hash iteration order. C<HV> and C<XPVHV> sizes are unchanged.
The ordinary hash index is capped at C<2^30> slots, supporting at most
715,827,882 live keys at its two-thirds load limit. Inserting beyond this
count or explicitly pre-sizing beyond it throws
C<Hash key count exceeds limit of 715827882>.

All builds encode the indexed bucket count and tiny-storage state in the
existing C<xhv_max> field, without enlarging C<HV> or C<XPVHV>. For indexed
storage, the low six bits hold the bucket-count exponent. Tiny storage sets bit 6
as a form tag and stores its capacity in the low six bits. The encoding is
independent of pointer width and works on 32-bit builds. C<HvMAX(hv)> remains
the logical accessor, returning the bucket mask for indexed storage and the
logical maximum for tiny storage. Use the form-specific setters; do not read
or write C<xhv_max> directly. Paired benchmarks found no broad slowdown, but
do not establish a general speedup.

The header C<hv.h> enables C<PERL_HASH_INDEX_CHAINS> by default unless
C<PERL_HASH_INDEX_OA> is selected. C<PERL_HASH_CHAIN_FINGERPRINT> enables
fingerprints for chains. Selecting OA together with either chains or
fingerprints is rejected. C<PL_strtab> remains open-addressed in every build.
The default chain index retains the compact entry array and tiny-hash form.
It uses power-of-two buckets, a packed bucket-head array, and a packed
next-identifier array with one link per entry slot. Identifiers are one-based
and zero marks an empty bucket or chain end. Their width follows entry
capacity, including holes: one byte through 255 entries, two bytes through
65,535, and four bytes above that. Widening these arrays does not move the
entry array; bucket resizing and entry compaction rebuild the chains.

In the default chain layout, entry storage starts at eight slots and grows by 25
percent when full, independently of bucket capacity. Entry compaction uses a
20 percent hole threshold at all capacities, with no byte threshold. A full
entry array compacts at this threshold while retaining the bucket count. A
non-full array compacts at this threshold when its proposed entry capacity,
C<live + floor(live/4) + 1> (minimum eight), is at most half its current
capacity. These are standalone insertion checks. An index rebuild that is
otherwise required also packs entries at this threshold, but does not apply
the standalone HE shrink test. Otherwise a full entry array grows by 25
percent without changing the bucket array. When live
entries reach two-thirds of bucket capacity,
the index grows to the next power of two that can hold C<3 * live> entries,
with a minimum of eight buckets. Compaction normally keeps the bucket count.
It shrinks the bucket array only when its target, the next power of two at
least C<3 * (live + 1)>, is at most half its current capacity. The entry
array can shrink independently when its target capacity,
C<live + floor(live/4) + 1> (minimum eight), is at most half its current
capacity. C<hv_ksplit()> pre-sizing uses a baseline of 1.5 times the
requested
count and reserves entry space for that count. Promotion from the tiny linear
form uses the baseline open-addressed sizing policy.

The optional build-time option C<PERL_HASH_CHAIN_FINGERPRINT> stores an 8-, 16-,
or 32-bit hash fingerprint with each entry link. Lookup checks it before
loading the candidate entry and its C<HEK>. This can avoid key-record reads
for misses at the cost of a larger link array. The next-identifier array adds
memory proportional to entry capacity in addition to bucket heads. Fingerprints
are disabled by default. To select the open-addressed layout, do a clean build
with C<-DPERL_HASH_INDEX_OA> applied to all objects; for example:

    make clean
    ./Configure -S -Doptimize='-O3 -DPERL_HASH_INDEX_OA'
    make -j4 test_prep

Shared-key interning now uses an open-addressed array of C<HEK *> pointers with
tombstones. Each shared C<HEK> has a C<U32> reference-count prefix, giving
a 12-byte header for count, hash, and length. Reference acquisition checks
for overflow. Its address remains stable while referenced, including when the
slot array grows. Capacity, probe positions, and tombstone count use
native-size integers. The pointer index has no fixed C<2^26> slot limit; its
growth is limited by checked allocation arithmetic and available memory. The
cached hash and reference count in each C<HEK> remain C<U32>. Since the hash
is 32 bits, hash distribution can limit performance above C<2^32> slots. This
does not change the ordinary hash index's C<2^30> slot limit. The table has a
minimum capacity of 32,768 slots. Before insertion, when live
entries plus tombstones reach C<floor(2*index_capacity/3)>, it targets the
next power of two able to hold three times the live entries, while retaining
the minimum capacity. It grows when tombstones are below half the occupied
slots. Otherwise it clears tombstones at the same capacity, except that it
shrinks when the target is at most half the current capacity. It has no
entry-array compaction or early shrink check. Traversal scans
the entry array independently of hash
values. The C<PERL_PERTURB_KEYS> controls and
C<Hash::Util::hash_traversal_mask> are removed. Hash-function seeding is
retained. Insertion during an active traversal is detected without random
state.

This changes the XS ABI and direct-storage interfaces. C<HeNEXT> and
C<HeSHARED_NEXT> are removed. C<HvMAX> is no longer writable as an
lvalue; use C<HvMAX_SET> or
C<HvMAX_SET_LINEAR> according to storage form. C<HE *> and C<SV **> pointers
into a hash must be reacquired after insertion or preallocation that can
compact or grow the entry array, and after deletion from a headerless linear
hash, which shifts later entries. See
L<perlguts/Working with HVs> and
F<Porting/hash-oa-design.pod> for the experimental compatibility limits.
C<Hash::Util::hash_storage_info> reports capacities, tombstones, probe
distances, and allocation sizes.
C<Hash::Util::shared_key_refcount> looks up a shared key's reference count
without interning it, and C<Hash::Util::shared_keys> returns copies of the
interned key strings. C<Hash::Util::immortalize_key> interns a key and
acquires one permanent reference per call, retained until interpreter
destruction and copied into cloned interpreters. Hash::Util bucket diagnostics do not expose
C<PL_strtab>; generic value-entry and iteration APIs do not apply to it.

=head1 Selected Bug Fixes

XXX Important bug fixes in the core language are summarized here. Bug fixes in

XXX Include references to GitHub issues and PRs as: [GH #12345] and the release

[ List each fix as an =item entry ]

=over 4

=item *

XPerl no longer evaluates the boolean overload of a C<$SIG{__DIE__}> handler
before invoking it. Callable overloaded handlers no longer cause recursive
exception delivery and a stack overflow.

=item *

A case-insensitive regex trie no longer accepts a word ending partway through
an input character's fold. For example, C</s|zoo/iu> no longer matches a
sharp-s, whose full fold is C<ss>. Later alternatives are tried in order.

=item *

A folded regex trie now updates its minimum and maximum lengths independently.
An alternative which changes both bounds could previously cause a valid
match to be missed or an assertion failure during Aho-Corasick scanning.

=item *

Case-insensitive trie prefix extraction no longer splits a multi-character
fold between regex nodes. For example, a UTF-8 flagged C<ssx|sy> pattern
under C</iu> now matches C<"\x{df}x">.

=item *

A case-insensitive regular expression with a folded literal start class
could loop indefinitely when searching at the end of a UTF-8 string.
This could occur on a subsequent C</g> match after a successful match.

[GH #24934]

=item *

Perl skips queued C<UNITCHECK> and C<CHECK> blocks when the main program
fails to compile. An explicit C<exit> during compilation retains the existing
behavior of running those blocks.

=item *

XXX

=item *

L<perlfunc/caller> is better able to identify the correct call site when
multiple branches of an C<if>/C<elsif>/C<else> chain call the same function.

=item *

L<B::Xref> is able to use line numbers stored within nulled COPs. [GH #7947]

=item *

Perl 5.44.0 introduced some internal changes that broke uses of C<substr> when
the string argument it is operating on was itself a special lvalue scalar
created by another C<substr> call. This would cause debugging assertions or
invalid C<free()> crashes from code that had a structure such as the following
examples:

    my $ref = \substr($str, $offset);
    substr($$ref, 0, 1, "replacement");

Z<>

    substr(substr($str, $offset), 0, 1, "replacement");

This bug has now been fixed. [GH #24933]

=item * Properly initialize ${^UTF8CACHE} in new threads

Previously the UTF-8 cache wasn't enabled in new threads, leading to performance issues.

=back

at L<https://github.com/Perl/perl5/issues>. There may also be information at
