=head2 Experimental data-shape matching

The experimental C<case_match> feature adds a C<case> statement with ordered
C<match> clauses.  Data shapes can match scalar values, nested array and hash
references, regular expressions, wildcards, and pinned lexical values.  A
case subject may also use the grammar-level C<ToInteger>, C<ToFloat>, or
C<ToString> forms to request one explicit coercion before matching.  Numeric
criteria include C<IntStr>, C<FloatStr>, C<Num>, C<NumStr>, and the
matching-only C<NumEq>; C<Strict> can request canonical spelling for the
string-bearing criteria.  See L<perlcasematch> and
L<perlsyn/Experimental Data-Shape Matching> for the current experimental
design and limitations.  The C<with> clause accepts a comma-separated list of
pins, and its case-local C<as> syntax does not require the separate
C<namespaces> feature.

Data shapes may also use zero-argument function and method calls as scalar
values.  Calls are made in scalar context when their clause is tried; calls
with arguments remain unsupported.  Repeating a constant data shape produces
a C<syntax> warning because the later clause can never match; the first clause
remains selected.  The warning includes the repeated constant and its source
location.

Static regular expressions used by open array or hash shapes are compiled once
and reused for each candidate.  Regex code blocks, C<(?{ ... })> and
C<(??{ ... })>, are currently rejected while a case pattern is compiled so
that their side effects cannot be silently discarded.  Unicode and byte-string
behavior remains under the control of the regular-expression engine.  Dynamic
regular expressions, such as C</thing-$re-thing/>, are also rejected in a
data-shape pattern; use an ordinary Perl guard after C<if> when the regular
expression must be built or interpolated at run time.

Array data shapes may capture a final tail with C<@name>, or require a minimum
tail length with C<@name:N>.  The typed criteria C<RefVal>, C<ScalarVal>, and
C<ObjectVal> may each take one scalar target, such as C<RefVal($reference)>,
which is bound after the type check succeeds.  Such a target cannot also be
pinned by C<with>.

Blessed references may use a class-qualified data shape.  Hash object shapes
check quoted field names, array object shapes check positional values, and a
reference object shape can bind a scalar referent.  These patterns inspect the
object structure directly without calling constructors, accessors, overload
methods, or arbitrary user methods.  The initial implementation covers blessed
hash, array, and scalar references; richer class-field metadata and roles are
future work.

An existing scalar can also be pinned directly in a data shape with the
pattern-only C<^$name> form.  Its value is snapshotted when the surrounding
C<case> begins, and ordinary caret operators retain their normal meaning
outside C<match> data shapes.

String shapes may contain multiple unbound scalars inside literal
concatenation, for example:

    case ($text) {
        match ("a" . $first . "b" . $second . "c") {
            say "first=$first second=$second";
        }
    }

Captures are resolved from left to right using the shortest value bounded by
the next literal or pinned fragment.  Empty captures are allowed.  Adjacent
unpinned captures, repeated capture names, and fragments separated only by an
empty literal are errors.  A name listed by C<with>, or written with the
pattern-only C<^> prefix, is a pinned existing lexical and must match its
snapshotted value rather than capture new text.  Concatenation supports only
literal, capture, and pinned fragments; arithmetic, calls, and other
unsupported expressions throw an exception.

More generally, unsupported or ambiguous data-shape syntax is rejected
explicitly.  It is never silently ignored, treated as a non-match, or
reinterpreted as ordinary Perl code.  See L<perlcasematch> and L<perldiag>
for the current rules and diagnostics.

=head2 Lexical namespaces

The experimental C<namespaces> feature provides lexical namespace prefixes,
the C<namespace> declaration and block form, C<__NAMESPACE__>, and lexical
package aliases using C<use ... as ...>.  See L<perlnamespace>.

=head2 Undef-aware equality operators

Four new operators have been added, which are similar to the regular equality
operators except for their handling of C<undef>. Whereas the regular operators
treat C<undef> as equal to the empty string or the number zero, these operators
consider C<undef> to be a distinct value, equal to itself, but unequal to any
defined value.

    if( $x equ $y ) {
      # $x and $y are both undef, or
      # $x and $y are both defined and equal
      ...
    }

This is approximately equal to the following, except that it is more
efficient and avoids duplicate evaluation of operands or fetching of tied
scalar values:

    if( (!defined $x and !defined $y) or
      (defined $x and defined $y and $x eq $y) ) {
      ...
    }

For more detail, see L<perlop/Equality Operators>.

=head2 Experimental generators

The experimental C<generator> feature creates a callable one-shot generator
from a block.  Each call resumes the block until its next C<yield>,
returning the yielded list in list context or its first value in scalar
context.  Separate generators can be resumed in an explicitly interleaved,
cooperative-concurrency pattern.  Generator calls can also send arguments
back to the suspended C<yield>.  See L<perlfunc/gen
BLOCK> and L<perlgenerator> for details.

The C<running>, C<completed>, C<failed>, and
C<exhausted> predicates are methods on generator objects and functions in the
C<generator::> package.  The C<generator> pragma enables the feature and makes
the package interface available.

=head2 Callable iterators

The experimental C<iterator> package can bless an ordinary code reference as
a callable iterator.  Its lifecycle can be inspected with the C<running>,
C<completed>, C<failed>, and C<exhausted> predicates and changed with
C<set_state>.  An iterator remains callable as the same code reference, and
an uncaught exception escaping its body is rethrown without automatically
changing its state; the implementation or caller may explicitly mark it
failed.  Generators inherit this protocol while continuing to manage their
continuation state internally.  See L<perlgenerator/CALLABLE ITERATORS>.

=head2 Complete experimental APIs with C<-E>

The C<-E> command-line switch now enables the complete experimental feature
set and imports the complete builtin set, including the generator syntax and
its supporting builtins.  This is an XPerl extension to the traditional
version-bundle behaviour of C<-E>.

=head2 Data::Dumper supports class objects

C<Data::Dumper> can now dump objects created by the experimental C<class>
feature.  It represents their fields with the experimental
C<builtin::class_object_to_hash> API and emits code using
C<builtin::class_object_from_hash> to recreate the object without invoking
its constructor.  Field values are shared rather than recursively copied.

=head2 Localizable random number generators

The new C<${^RNG}> variable can be localized to select a user-supplied random
number generator for C<rand> and C<srand>.  An object provider implements
C<rand_bytes> and C<srand> methods; an unblessed code reference is called
directly.  The provider supplies the requested number of random bytes to
C<rand>, while C<srand> passes the supplied seed to the provider.  This
permits custom generators to accept seed values that the default generator
would reject.

When C<${^RNG}> is undefined, Perl continues to use its normal random number
generator.  The provider's state is independent of Perl's default generator,
and localizing C<${^RNG}> does not copy or restore that state.  See
L<perlrng>, L<perlfunc/rand EXPR>, and L<perlvar/${^RNG}> for more information.

An XS provider may also implement the optional
C<get_rand_u64_XS_func_addr> method.  When it returns a valid callback
address, C<rand> can obtain 64-bit words without Perl method dispatch; the
ordinary C<rand_bytes> interface remains the portable provider protocol.

Only C<undef>, an object, or an unblessed C<CODE> reference may be assigned to
C<${^RNG}>.  Other scalar values, including values assigned through C<local>,
are rejected immediately.

=head2 Magic v2

This version introduces a whole new set of API functions, data structures, and
related items that provides a new kind of variable magic; providing the
ability to attach user-supplied trigger functions to behaviours on existing
variables.

The eventual intention of this new version is to extend magic with new trigger
functions that can apply at different times to those currently supported, and
to allow magic to be attached to new kinds of items than are currently
permitted. Right now as of this iteration, it does not offer any new abilities
but simply changes the shape and structure of existing things to allow space
for those extensions to be made at a later date.

For more details, see L<perlguts/Magic v2>.

=over 4

=item *

Common list slices of C<caller> return values will be more efficient.
Specifically, C<caller> will output only the required values indicated by
slice subscript(s) with no actual slicing being necessary.

This has been implemented such that the OP type of C<caller> need not
change and with minimal modification to the function internals, but
consequently not every conceivable slice can be optimized.

The most common slices seen in core and on CPAN are supported.
Specifically, any of the following single subscripts
(e.g. C<(caller $depth)[3]>) or an ascending run of these subscripts
(e.g. C<(caller $depth)[8,9,10]>) will be optimized:

=over 8

=item *

0 - package

=item *

1 - filename

=item *

2 - line

=item *

3 - subroutine

=item *

8 - hints

=item *

9 - bit mask

=item *

10 - hint hash

=back

[GH #23369]

=item *

XXX

=item *

The regular expression trie optimizer has been reworked to compile trie
transitions as octets.  Large alternations can now avoid work that previously
grew with both the number of alternatives and the amount of text skipped
before a match, while preserving the existing matching semantics for native
and UTF-8 strings.

=back

=head1 Internal Changes

XXX Changes which affect the interface available to C<XS> code go here. Other
significant internal changes for future core maintainers should be noted as
well.

[ List each change as an =item entry ]

=over 4

=item *

During regex compilation, C<S_reg> will attempt to flatten nested BRANCH
structures, in an attempt to give the TRIE optimizer more alternations
to consider. The intent is that patterns that were previously compiled
into two or more adjacent TRIE nodes might now get compiled into a single
(or at least, fewer) TRIE node(s).

=item *

XXX

=item *

The regular expression compiler's TRIE implementation has been changed to use
the octets of the UTF-8 representation of the pattern in its internal table
structures. Previous versions used a trie based on code points, which had
various side effects that required additional complexity, especially because
of Unicode's potentially very large alphabet. By switching to an octet-based
representation, a large amount of this complexity could be removed, making
the new code faster, easier to maintain, and easier to prove correct.

Most users should not notice this change, except perhaps a slight performance
improvement.

=back

=over 4

=item *

Since 5.28.0, the numeric value of a string would sometimes not get reset
after the string was assigned to as part of a string concatenation. It
required the following circumstances to all be present for the bug to
manifest:

=over

=item *

the string variable must be zero length and have just been used in numeric
context, e.g. C<$s = ""; $n = $s + 1;>

=item *

then the variable must be the target of a string concatenation and also
be used on the RHS, e.g.C<$s = "9$s";>

=item *

then if the string is used in numeric context again, the bug caused the
old numeric value of 0 to be returned, rather than numifying the new
string value and returning 9.

=back

[GH #24763]

=item *

Parsing an invalid signature that gives a slurpy parameter a default value no
longer crashes when parser debugging is enabled.  [GH #24691]

=item *

Copy magic to the new elements when splice() inserts elements into a
non-tied magical array.  In particular, assignment to an element of an
C<@ISA> array where the element was added by splice() is now correctly
recognized when performing method lookup.  [GH #24659]

=back

=head1 Reporting Bugs

If you find what you think is a bug, you might check the perl bug database
at L<https://github.com/Perl/perl5/issues>. There may also be information at
L<https://www.perl.org/>, the Perl Home Page.

If you believe you have an unreported bug, please open an issue at
L<https://github.com/Perl/perl5/issues>. Be sure to trim your bug down to a
tiny but sufficient test case.

If the bug you are reporting has security implications which make it
inappropriate to send to a public issue tracker, then see
L<perlsec/SECURITY VULNERABILITY CONTACT INFORMATION>
for details of how to report the issue.
