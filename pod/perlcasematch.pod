=head1 NAME

perlcasematch - a gentle introduction to experimental case and data-shape matching

=head1 DESCRIPTION

This document introduces Perl's experimental data-shape matching feature.  It
assumes that you know a little Perl, but not that you have used this kind of
matching in another language.

Data-shape matching asks two questions at once: does a value have the shape we
want, and which parts of it should receive names?  It combines structural
matching with destructuring.  We use the shorter term C<data-shape matching>
to distinguish this feature from Perl's long-established regular-expression
pattern matching.

The feature is enabled with:

    use feature 'case_match';

It is experimental, so its spelling and behaviour may change.

=head1 THE BASIC IDEA

A C<case> examines one subject and tries its C<match> clauses from top to
bottom.  The first matching clause runs.  Clauses do not fall through.  The outer
case block may contain only direct C<match> clauses; an ordinary statement or a
nested C<case> is not allowed there.  Each clause's attached block is an
ordinary Perl block and may contain normal Perl statements, loops, and nested
cases.

It is important to keep in mind that the data-shape is *not* perl, and while
its syntax is as perlish as possible, its syntax is limited and intended for
describing a data structure, and is not intended to be executed in the normal
way.

    use feature 'case_match';

    case ($value) {
        match (1) { say "one" }
        match (2) { say "two" }
        match (_) { say "something else" }
    }

The underscore is a wildcard. It matches any value and does not create a binding,
so it is useful as a final default clause. This is a good example of the data-shape
part of the match operatore following different rules than normal perl where the
underbar would mean something else.

If no clause matches, the C<case> expression returns C<undef> in scalar context
and an empty list in list context.  A wildcard clause is the usual way to give
the case a default action.

=head1 BINDING VALUES

A scalar variable in a data-shape description is an implicit lexical name to
be filled in when the data shape matches.  You do not write a separate C<my>
declaration for it:

    case ($person) {
        match ({ name => $name, age => $age} if $age < 18) {
            say "$name is a minor";
        }
        match ({ name => $name, salary => $salary, ... }) {
            say "$name earns $salary";
        }
    }

Bindings are tentative.  Perl does not change the variables while it is
deciding whether the complete data shape matches.  If a later part fails,
earlier bindings are discarded.  The names become available only after the
complete data shape, and its guard if any, succeeds.

Data-shape variables are lexical to the block attached to that C<match>.  They
are not accesses to a same-named variable in the surrounding scope, and they
do not become variables there.  A name listed by the case's C<with> clause, or
prefixed with C<^> in the data shape, is the exception: it is pinned and is
looked up as the existing lexical.

The leading part inside C<match (...)> is a data-shape description, not
an ordinary Perl expression. It has Perl-like punctuation and names, but
its job is to describe the shape of the subject and introduce bindings.
It is not executed to produce a temporary Perl value.  The optional trailing
part after C<if> is different: it is an ordinary Perl expression, evaluated
as a guard after the data shape has matched and its bindings have been
tentatively established.

Within a data shape, repeating an unpinned scalar name refers to the same
binding.  This both binds the value and requires later occurrences to have
the same value.  Whole-array bindings like C<@values> are supported, but
whole-hash bindings such as C<%values> are currently not supported.

=head1 SCALAR PATTERNS

Literal numbers and literal strings are different data shapes:

    case ($value) {
        match (1)   { say "the number one" }
        match ("1") { say "the string one" }
    }

The number data shape is intended for a numeric scalar and the string data
shape for a string scalar.  This is deliberately more explicit than ordinary Perl
comparison where the type of comparison is determined by the operator used;
since there is no operator in this construct we take this approach to distinguish
numeric and string matches.

An undefined value can be matched directly:

    case ($value) {
        match (undef) { say "no value" }
        match (_)     { say "some value" }
    }

The boolean data shapes C<true> and C<false> use Perl's ordinary truth-value
rules.  They match the subject according to perls definition of boolean truth
rather than requiring the subject to be one of the internal boolean scalar objects.
For example, C<match (true)> also matches the number C<1>, while C<match (false)>
matches C<0>.  Use C<match (undef)> when the distinction between an undefined value
and a defined false value matters.

=head2 Zero-argument constant calls

A zero-argument function or method call may be used when a data shape needs a
value supplied by Perl code rather than a literal.  The call is made in
scalar context when the clause is tried, and its result is compared with the
subject using the same typed rules as a literal value:

    sub current_version { 3 }

    case ($version) {
        match (current_version()) { say "current" }
        match (Version->number()) { say "known version" }
    }

This is a deliberate, small exception to the general rule that the left side
of C<match> is a data-shape description rather than ordinary Perl code.  Only
calls with no arguments are supported.  A call such as
C<current_version($kind)> is rejected; use a guard after C<if> when ordinary
Perl computation or arguments are needed.  Calls can have side effects, so
they should be used only when that behavior is intended.

=head2 Value-kind criteria

Sometimes the shape you want is about the kind of value, rather than its
contents.  The following criteria are available inside C<match (...)>:

=over

=item C<RefVal()>

Matches any reference, including an unblessed array or hash reference and a
blessed object.

=item C<ScalarVal()>

Matches any non-reference scalar.  This includes C<undef>, numbers, and
strings.

=item C<ObjectVal()>

Matches a blessed reference.  It is therefore a narrower test than
C<RefVal()>: an unblessed reference matches C<RefVal()> but not
C<ObjectVal()>.

=back

These criteria describe the subject's value kind.  They do not dereference a
reference, call a method, or inspect an object's class.  Within a C<match>
description these spellings are criteria, not ordinary function calls.  The
names retain ordinary Perl subroutine semantics elsewhere, so a program may
define or call a function named C<RefVal>, C<ScalarVal>, or C<ObjectVal>.
[XXX: Follow up, should the user defined one take precedence if it is available?]

Each criterion may also take one scalar pattern target.  The target is bound
to the value after the type check succeeds:

        case ($value) {
            match (RefVal($reference)) { use_reference($reference) }
            match (ObjectVal($object)) { use_object($object) }
            match (ScalarVal($scalar)) { use_scalar($scalar) }
        }

The target is an implicit, clause-local binding, just like a scalar name used
elsewhere in a data shape.  It must not be one of the values pinned by the
C<with> clause.  A criterion without an argument performs the type check
without binding a value.

=head2 Numeric value criteria

Numeric data shapes distinguish native numeric values from numeric-looking
strings:

=over

=item C<IntStr()>

Matches an integer value or a string containing an integer.  Surrounding
whitespace and leading-zero padding are accepted.

=item C<FloatStr()>

Matches a floating-point value or a string containing a floating-point number.
Exponent notation is accepted.  Surrounding whitespace and leading-zero
padding are accepted.

=item C<Num()>

Matches a native integer or floating-point value.  A string is not converted
just to make it fit this shape.

=item C<NumStr()>

Matches anything accepted by C<IntStr()> or C<FloatStr()>.

=item C<NumEq()>

Matches as though comparing the two values using numeric equivalence. This
is special as compared to the others in that it cannot be used to bind a value,
only to match one. Use NumStr() if you want to capture.

=back

These criteria can also bind their matching value.  The binding receives the
original value; matching C<"0007"> does not turn the binding into C<7>:

    case ($value) {
        match (IntStr($integer_text)) { use_integer($integer_text) }
        match (FloatStr($float_text)) { use_float($float_text) }
    }

C<Strict(...)> may wrap C<IntStr()>, C<FloatStr()>, or C<NumStr()> when a
canonical spelling is required.  Strict numeric string criteria reject
surrounding whitespace and non-canonical leading-zero padding.  C<Strict(Num())>
and C<Strict(NumEq(...))> are compile-time errors: C<Num()> already requires a
native number, and C<NumEq()> is not a destructuring criterion.

As mentioned above C<NumEq(EXPR)> is different from these criteria.  It is a
matching-only comparison using Perl's ordinary numeric C<==> semantics.  It cannot
bind a value.  For now, C<EXPR> must be a literal value.  Non-numeric input
that matches [XXX: verify and if not true then fix] but will produce the usual
warnings when appropriate:

    case ($value) {
        match (NumEq(0)) { say "numerically zero" }
    }

Thus C<NumEq(0)> matches C<"0000">, C<"0.0">, and C<"0000.0">, as well as C<"A">
but with warnings.

=head1 OBJECT AND CLASS SHAPES

A blessed reference can be matched by putting its class name before an array,
hash, or reference shape.  The class name is checked first; the shape then
describes the contents of the blessed reference.  No constructor, accessor, or
other method is called to inspect the object.

For a blessed hash reference, quoted keys describe the object's fields:

    my $point = bless { 'x' => 3, 'y' => 4 }, 'Point';

    case ($point) {
        match (Point { 'x' => $x, 'y' => $y }) {
            say "point: $x,$y";
        }
    }

Hash object shapes are exact unless they end with C<...>.  The ellipsis allows
additional fields.  The field values use the ordinary data-shape rules, so
they may be literals, captures, nested shapes, or pinned values.

A blessed array reference uses a positional shape:

    my $pair = bless [ 10, 20 ], 'Pair';
    case ($pair) {
        match (Pair [ $first, $second ]) {
            say "$first and $second";
        }
    }

A blessed scalar reference can bind its referent with a reference shape:

    my $value = 42;
    my $boxed = bless \$value, 'Box';
    case ($boxed) {
        match (Box \$number) { say $number }
    }

These forms are structural.  They do not use constructors, accessors, or
arbitrary user methods.  Native Perl class objects backed by the class
field-map representation are also supported.  A class-qualified shape
requires the exact named class in this version; an inherited class or role
does not satisfy it.  A missing field is a non-match.  Field values then use
the ordinary data-shape rules: tied or magical values follow normal read
semantics, and overload is used only when the selected pattern requires a
string, numeric, or boolean conversion.  Captured references retain their
identity.  An inheritance test such as an C<isa> pattern may be introduced
in a future version of the matching.

=head2 Regular-expression data shapes

A regular expression can be used as a data shape.  It is applied to the case
subject, and matches as would be expected. If the pattern captures then the
ordinary regular-expression capture variables are available in the clause:

    case ($text) {
        match (/^user: (\w+)$/) {
            say "user is $1";
        }
        match (/^person: (?<person>\w+)$/) {
            say "person is $person";
        }
    }

In addition, should the pattern include named captures then they automatically
become clause-local scalar bindings.  They are copies of the
values selected by the regular expression, so the clause can use C<$person>
directly.  The normal regular-expression variables, such as C<$1> and
C<$+{person}>, are also updated and remain available.  A named capture that did
not participate in a successful match is still bound to C<undef>.  Should a
name be mentioned twice then the binding will end up with the same result
as C<$+{name}> would (the leftmost matching case).  If you need access to which
matched you should inspect C<$-{name}>.

The regular expression is still a regular Perl regular expression.  Its
ordinary matching behavior, including its capture rules, applies.  The
regular expression is compiled only once, and may be applied repeatedly while an
open array or hash shape searches for a candidate.
Dynamic regular expressions, such as those using interpolation or code block
patterns like C<(?{ ... })> and C<(??{ ... })>, are not currently supported
in a data-shape regex and will trigger an exception when the pattern is compiled.
This restriction may be revisited in the future, until then you may put such a
regular expression in guard clause instead, for example

    match (_ if $subject =~ /thing-$re-thing/) { ... }

Using a regular expression as one fragment of a larger string data shape is
unsupported.

As with any other block the capture state is localized to the C<case> block.
When the case ends, the previous values of C<$1>, C<$2>, C<%+>, C<%->, and related
match variables are restored.

=head2 Concatenated string data shapes

A string data shape can combine literal text with unpinned scalar names.  Each
name receives the part of the subject between the surrounding literal pieces:

    case ($text) {
        match ("x_" . $middle . "_z") {
            say "middle is $middle";
        }
    }

This matches C<x_middle_z> and binds C<$middle> to C<middle>.  Several captures
are allowed when they are separated by a literal or pinned value:

    case ($text) {
        match ("a" . $first . "b" . $second . "c") {
            say "first=$first second=$second";
        }
    }

The matcher works from left to right.  For each capture it chooses the
shortest value that reaches the next literal or pinned value.  In the example,
the first C<$first> ends at the first C<b>; the final capture receives the
remaining text up to C<c>.  A literal may appear on only one side as well, as
in C<"x" . $suffix> or C<$prefix . "z">.  An empty capture is valid, so C<x__z>
matches the first example with an empty C<$middle>.

Every capture name may occur only once in a concatenation.  Adjacent unpinned
captures are not allowed because there is no boundary that tells the matcher
where one ends and the next begins:

    # Both forms are errors.
    match ($first . $second) { ... }
    match ("a" . $first . "-" . $first) { ... }

These restrictions are checked explicitly.  An unsupported operator, call, or
other expression in the structural part is an error; it is never silently
ignored or treated as ordinary Perl.  Use the guard after C<if> for ordinary
Perl computation:

    match ("prefix_" . $name if length($name) > 2) { ... }

The concatenation is interpreted as a data shape, not as an ordinary Perl
expression.  [XXX: capture var and pinned var documentation needs its own
section at the top before more complicated ideas are introduced.]  A scalar
named in a C<with> clause, or prefixed with C<^>, is pinned and contributes
its existing value instead of capturing text:

    my $text = "xblah";
    my $wanted = "blah";
    case ($text) with ($wanted) {
        match ("x" . $wanted) { say "it matched" } # matches
    }

Concatenation is the only structural expression currently supported.  A
function call with arguments, arithmetic expression, or other operator inside
the concatenation is not a way to compute a data shape.  Use the guard after
C<if> for ordinary Perl computation.  Literal strings and values with normal
stringification, including usable overloaded stringification, follow ordinary
Perl string and Unicode/byte semantics; concatenation does not perform a
separate numeric coercion step. [XXX: reword in CS-101 voice, avoid excessive
references to Perl. Also audit entire doc for excessive references to "Perl"

=head2 Reference shapes

A backslash can describe a reference shape.  C<\$name> matches a reference to
a scalar and binds the scalar that it refers to:

    my $number = 42;
    my $reference = \$number;

    case ($reference) {
        match (\$value) { say "the referenced value is $value" }
    }

Reference shapes can be nested.  C<\\$name> matches a reference whose referent
is itself a scalar reference, and binds the innermost scalar value.  A
reference shape is structural: it does not evaluate the pattern as an
ordinary reference constructor.  The binding is tentative and is committed
only when the complete clause, including its guard, succeeds.

C<RefVal($name)> is different.  It checks for any reference and binds the
outer reference itself, while C<\$name> binds the value reached through a
scalar reference.  The current reference-shape implementation covers scalar
and nested scalar references; array and hash reference constructors remain
ordinary composite data shapes. [XXX: tortured wording]

An array data shape matches an array reference.  Without an ellipsis, it must
have exactly the listed number of elements:

    case ($point) {
        match ([ $x, $y ]) { say "point: $x, $y" }
    }

A hash data shape lists keys which must be present.  A trailing C<...> allows
additional keys:

    case ($record) {
        match ({ status => "ok", value => $value, ... }) {
            use_value($value);
            }
    }

For arrays, C<...> can be used at the beginning, at the end, or at both ends:

    match ([ $first, ... ])
    match ([ ..., $last ])
    match ([ ..., "start", $middle, "end", ... ])

The last form searches from the left and binds the first matching subsequence.
Array and hash data shapes can be nested in one another.  An ellipsis may be
used only at the supported open-shape positions shown above; it is not a
general wildcard for arbitrary positions.

An array data shape can capture its remaining tail with an array binding.  The
binding is allowed to contain zero or more elements:

    case ($values) {
        match ([1, 2, @rest]) { say "the rest is @rest" }
    }

The binding must be the final pattern element.  Add C<:N> to require at least
C<N> remaining elements while still capturing the complete tail:

    match ([1, 2, @rest:3]) { say "three or more: @rest" }

The initial implementation permits one final slurp and a minimum from 0
through 255.[XXX: arbitrary restriction should be removed]  A slurp cannot be
combined with an ellipsis or with another slurp.  Like scalar bindings, the
array binding is tentative until the whole data shape and its guard have
succeeded.

=head1 GUARDS

[XXX: should be earlier in document]

A guard is an ordinary Perl expression checked after the data shape has
matched structurally:

    case ($value) {
        match ([ $number ] if $number > 0) {
            say "positive: $number";
        }
        match (_) { say "not a positive one-element array" }
    }

The C<if> and everything after it belong to ordinary Perl.  Guards are
unrestricted Perl expressions.  They may have side effects or
throw exceptions.  If a guard is false, that clause's tentative bindings are
discarded and the next clause is considered.  If a guard throws, the exception
is propagated in the usual way; the tentative bindings are still discarded.

=head1 NAMING AND PINNING

[XXX: should be earlier in document]

The subject can be given a case-local name with C<as>:

    case (read_record() as $record) {
        match ({ type => "ok", ... }) { use_record($record) }
    }

This evaluates the subject once and does not assign to an outer variable.

A C<with> clause pins an existing value.  A pinned variable is checked rather
than filled in by the data shape:

    my $wanted = "ok";
    case ($record) with ($wanted) {
        match ({ type => $wanted, ... }) { use_record($record) }
    }

The C<with> clause can pin more than one value.  Separate the values with
commas:

    my ($wanted_type, $wanted_version) = ("ok", 3);
    case ($record) with ($wanted_type, $wanted_version) {
        match ({ type => $wanted_type,
                 version => $wanted_version, ... }) {
            use_record($record);
        }
    }

There is also a shorter way to pin an existing scalar directly in a data
shape.  Put a caret before the scalar name:

    my $wanted = "ok";
    case ($record) {
        match ({ type => ^$wanted, ... }) { use_record($record) }
    }

Inside a C<match (...)> data shape, C<^$name> means “compare with the value
of this existing lexical”.  It does not create a new binding.  The value is
snapshotted when the surrounding C<case> begins, so all clauses see the same
pinned value even if a guard or clause body later changes the lexical.  [XXX:
verify this is true and make sure it is tested]  Only an existing scalar
lexical may follow the caret.  This meaning of C<^> is special to the
data-shape language; outside a match clause, Perl's ordinary caret operators
keep their normal meaning outside of data-shape descriptions..

An expression can be evaluated once and made into a case-local pin:

    case (func() as $record)
    with (expected_type() as $wanted)
    {
        match ({ type => $wanted, ... }) { use_record($record) }
    }

The C<as> spelling in a C<case> subject or C<with> clause belongs to this
featurei and is distinct (but similer) to the like named syntax which is
part of the namespace feature.  Each value in a C<with> list may use
C<as> independently.

=head1 EXPLICIT SUBJECT CONVERSION

The grammar provides three explicit subject conversions:

    case (ToInteger $value) { ... }
    case (ToFloat   $value) { ... }
    case (ToString  $value) { ... }

The subject is evaluated once and converted before any clause is tested.  An
undefined value remains undefined, and references pass through unchanged.

=head1 A COMPLETE EXAMPLE

This example classifies a small message represented by an array reference:

    use feature 'case_match';

    my $value = [ "ok", 42 ];

    case ($value) {
        match ([ "ok", $number ]) { say "received $number" }
        match ([ "error", $message ]) { warn $message }
        match (_) { say "unrecognised value" }
    }

=head1 WHAT WORKS NOW

The current experimental implementation supports scalar data shapes, lexical
bindings and pins, wildcards, regular-expression data shapes with ordinary and
named captures, nested array and hash references, open composite shapes,
guards, and explicit scalar subject conversion.  Constant-only cases without
guards also have optimized
dispatch paths.  The selected dispatch strategy is an implementation detail;
the first matching clause in source order still wins.
