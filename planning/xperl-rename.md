# Plan: rename AI Perl to XPerl

## Intent

Rename the experimental distribution currently called AI Perl to XPerl.
The working branch currently named `ai-perl` should become
`xperl/main`.  Tracked source and documentation references should use the
new terminology, while unrelated uses of `ai` or `AI` must remain unchanged.

The selected spelling is:

| Existing form | Replacement | Typical use |
|---|---|---|
| `ai-perl` | `xperl` or `xperl/main` | historical product name or branch URL, depending on context |
| `aiperl` | `xperl` | historical compact product/installation name |
| `AI-PERL` | `XPERL` | historical heading and maintainer identifier |
| `AI-PERL-MISSION.md` | `XPERL-MISSION.md` | mission filename |

Branch references in GitHub URLs must use `xperl/main`, not merely `xperl`,
because that is the new branch name.

## Current inventory

The tracked Perl checkout contains references in:

- `README`, `AI-PERL-MISSION.md`, `BLEAD-DELTA.md`, and `MANIFEST`;
- `Porting/Maintainers.pl`;
- `planning/generator_plan.md` and
  `planning/mainline-policy-inventory.md`;
- GitHub links embedded in the delta and README documents;
- generated or derived material associated with the current checkout.

The workspace-wide search also finds `ai-perl` in:

- `Coro-6.57/Makefile` and `Coro-6.57/Coro/Makefile`, which are generated by
  that module's build and contain absolute perlbrew paths;
- Git metadata (`perl/.git/config`, reflogs, and `blead/.git/FETCH_HEAD`);
- local installation/build state and other historical records.

The generated Coro Makefiles and Git metadata are not source references. They
should not be mass-rewritten. The Coro build files may be regenerated by
reconfiguring Coro against the renamed perlbrew installation after the source
rename, if that installation is being renamed too.

## Implementation phases

### 1. Public spelling map (decided)

- Use `XPerl` in prose and user-facing headings.
- Use `xperl` for compact identifiers and installation names.
- Use `xperl/main` for the main development branch and branch-specific GitHub
  links.
- The mission file is renamed to `XPERL-MISSION.md`; `MANIFEST`, README links,
  and references must remain consistent.
- The maintainer key in `Porting/Maintainers.pl` is `XPERL`; preserve the
  actual maintainer names.

### 2. Rename tracked files and tracked content

- Rename the mission file if approved.
- Update README branding, mission/delta links, and branch URLs.
- Update `BLEAD-DELTA.md`, including every link whose branch component is
  `ai-perl`.
- Update planning documents and any living plans that identify `ai-perl` as
  their working branch.
- Update maintainer metadata and any user-visible diagnostics or generated
  metadata that intentionally identifies the distribution.
- Search case-insensitively for both `ai-perl` and `aiperl` after editing.

Do not change references to unrelated terms such as `AI`, `ai`, or `aiperl`
when they are not identifying this distribution.

### 3. Regenerate and repair repository metadata

- Run the normal manifest and regeneration checks after source edits.
- Run `make manisort` if the mission-file rename or manifest changes require
  it.
- Do not hand-edit generated files; regenerate them from their sources.
- Review generated output for accidental product-name changes and update only
  files whose source or generated content is intentionally part of the rename.

### 4. Rename the local and remote branches

Only after the tracked content is ready and committed:

```sh
git branch -m ai-perl xperl/main
```

Then publish `xperl/main` to the `dmq` remote, verify it, update local branch
tracking, and delete the old `dmq/ai-perl` branch. The new remote branch must
be confirmed present before the old one is removed.

The rename should not rewrite reflogs or other historical Git records.

### 5. Rebuild dependent local installations when needed (out of scope here)

- No perlbrew installation or external distribution is being renamed by this
  task. Existing generated Makefiles outside `perl/` remain untouched.
- Keep workspace-local temporary output under `./tmp/` and use the absolute
  workspace `.ccache` path for rebuilds if a rebuild is needed.

## Validation

- `git grep -n -i -E 'ai[-_]?perl|aiperl' -- ':!*.git/*'` finds no unintended
  tracked product references; any retained occurrence must be documented as a
  historical or compatibility reference.
- `git diff --check` is clean.
- `git diff --name-status` shows the intended mission-file rename and only
  related content changes.
- `make regen` and `make regen_perly` produce no unexpected changes when the
  rename touches generated sources.
- Run focused README/manifest/maintainer/porting checks, then `test_porting`.
- Run `make_test` in window 3 after the tree is rebuilt.
- Verify Git state with `git branch --show-current`, `git status`, and the
  upstream configuration.
- Verify that GitHub links resolve to the new default branch path and that the
  old branch name is absent from current tracked documentation.

## Commit structure

Keep the work reviewable in separate commits:

1. tracked branding, mission filename, and documentation links;
2. maintainer/planning metadata and generated-file updates;
3. dependent local build/install regeneration, only if in scope;
4. local branch rename and upstream configuration, recorded separately from
   source commits.

Do not commit `.git` metadata, reflogs, temporary files, ccache contents, or
generated external-module build files unless their source distribution is
explicitly brought into scope.

## Rollback

Before the branch rename, revert source commits normally. After the local
branch rename, return to the old name with:

```sh
git branch -m xperl/main ai-perl
```

Remote branch changes, if any, require their own explicit rollback.
